# IPPO UI/UX Foundation Council

> ippoを「よくある健康記録アプリ」ではなく、
> 「女性向け体質改善実験プラットフォーム」として画面から伝わるアプリにするための設計文書。
>
> **本文書はコード変更を含まない。設計決定のみ。**
> Design System は `src/styles/app.css` の実測CSS変数を根拠とする（架空の数値を作らない）。

---

## 1. Product Concept

> **ippoは、自分の体で「小さな実験」を積み重ね、体質のパターンを発見していく女性のための実験ノート型アプリである。**

補足定義:
- 「記録アプリ」ではなく「実験ノート」。日々の記録は目的ではなく、実験の材料。
- ゴールは「継続」ではなく「発見」。続けること自体をご褒美にしない。発見が報酬になる設計にする。
- 対象ユーザーは、体調不良の原因を漠然と感じているが、何が原因か特定できていない女性。「特定する」体験を提供する。

この一文がすべての画面設計の判定基準になる。迷ったら「これは実験ノートに見えるか？記録帳に見えていないか？」で判断する。

---

## 2. UX Philosophy

5つの体験原則。それぞれに「画面設計上どう効くか」を紐づける。

### 2.1 毎日使いたくなる
- 開くたびに「何か新しい気づきがあるかもしれない」という期待を作る（Homeの気づきカードが日替わりで変化）。
- 開いた瞬間に今日の実験の進捗（Day X / 残り時間）が見える＝ゲームのセーブデータを開く感覚に近づける。

### 2.2 疲れない
- 1画面の情報ブロックはHome最大6・Insights同時表示4以内に制限する（既存のInformation Density Freezeを踏襲）。
- 文字より色・アイコン・グラフで状態を伝える。読ませるアプリにしない。

### 2.3 記録が億劫にならない
- Recordは3カード固定・すべてタップ選択（チップ/アイコン）中心。自由入力は任意の1行メモのみ。
- 「入力」ではなく「チェックイン」という体感にする（所要時間を10秒以内に収める設計）。

### 2.4 実験したくなる
- Experimentは「禁止・我慢」ではなく「試してみる小さな挑戦」として見せる（カード名・トーン・進捗表現）。
- Insightsで見つかったパターンから自然にExperimentへ導線を張る（「乳製品を摂った日に肌荒れが多い→乳製品断ちを試す」）。

### 2.5 自分の体を理解できる
- Insightsは「分析結果の一覧」ではなく「気づきのフィード」として設計する。グラフより先に「文章化された気づき」を見せる。
- 生理周期との重なりを常に横断的に示し、単発の記録ではなく周期の中の変化として理解させる。

## 3. App Structure（最小構成）

画面は5つに固定する（禁止事項: タブを増やしすぎない）。

| 画面 | 役割 | Home動線との対応 |
|---|---|---|
| **Home** | 起動後の最初の画面。全体のハブ | 気づく／次につなげる |
| **Record** | 今日のログを10秒で入れる | 記録する |
| **Insights** | パターンを発見する | 気づく／結果を見る |
| **Experiment** | 小さな挑戦を選ぶ・進める | 試す |
| **Me**（Settings / Premium・Proを内包） | 自分の設定・課金導線 | — |

補足:
- 「Record」はタブとしても存在するが、Home上の中央CTAからも直接開けるようにする（後述 9章）。
- Premium/Proは独立タブにしない。「Me」タブの中の1セクションとして提供し、必要な文脈（Insightsで制限にぶつかった時など）からもモーダルで直接呼び出せるようにする。これによりナビゲーションのタブ数を5に維持する。

## 4. Home Layout（最重要）

Home 1画面で「記録する→気づく→試す→結果を見る→次につなげる」の一周が伝わる設計にする。ブロックは最大6（Information Density Freeze準拠）。

```
┌─────────────────────────────┐
│ ① ヘッダー                    │  おはようございます／Day 12
│    今日の日付・実験Day数        │
├─────────────────────────────┤
│ ② 今日の記録カード（記録する）    │  未記録なら「10秒で記録」CTA
│    記録済みなら要約チップ表示     │  記録済み: 気分😊 睡眠7h 肌荒れなし
├─────────────────────────────┤
│ ③ 気づきカード（気づく）         │  1文の発見を毎日更新
│    「先週、乳製品を摂った日は     │  カードタップでInsights詳細へ
│     肌荒れの報告が3倍でした」    │
├─────────────────────────────┤
│ ④ 実験カード（試す）            │  進行中: プログレスリング＋Day表示
│    進行中 or おすすめ実験        │  未実施: 気づきから提案された実験
├─────────────────────────────┤
│ ⑤ 結果を見るカード（Insightsへ） │  簡易グラフのプレビュー＋「もっと見る」
├─────────────────────────────┤
│ ⑥ 次につなげるカード            │  「明日はカフェインを控えてみましょう」
└─────────────────────────────┘
```

設計原則:
- ②〜⑥は縦一列。横スクロールのカルーセルにしない（疲れない・迷わない）。
- ①は毎回同じ高さ・同じトーン。安心して開ける「定位置」にする。
- ⑥は必ず「明日1つだけ」の提案にする。複数提案しない（疲れない）。

## 5. Record Layout

入力項目を増やさず、3カード固定（Information Density Freeze準拠）。すべてタップ操作を基本とし、自由入力は最後の1カードの1行メモのみ。

```
┌─────────────────────────────┐
│ カード1: 今日の体調             │
│  気分 [😞 😐 🙂 😊 😄]         │  アイコンタップのみ
│  睡眠 [◐ スライダー or 5段階]   │
│  肌  [荒れ / 普通 / 良い]       │
├─────────────────────────────┤
│ カード2: 今日の行動タグ          │
│  [☕カフェイン][🥛乳製品]        │  チップ選択（複数可）
│  [🍚糖質][🍷アルコール]         │  実験中の変数は自動でハイライト
│  [🏃運動][💤 早寝]             │
├─────────────────────────────┤
│ カード3: 気づきメモ（任意）       │
│  1行テキスト入力                │  プレースホルダー:
│                                │ 「今日気づいたことがあれば」
└─────────────────────────────┘
         [ 記録する ]
```

設計原則:
- カード2のタグは「制限」ではなく「観察対象」として見せる（禁止色にしない。中立トーン＋実験中のものだけ rose でハイライト）。
- 保存後は必ずHomeに戻り、②のカードが即座に更新される（入力の手応えを即返す）。
- 入力項目数の上限はこのカード構成に固定し、将来的な追加はFounder承認必須（既存Freeze継承）。

## 6. Insights Layout

「分析画面」ではなく「気づきのフィード」として設計する。同時表示は最大4要素（Information Density Freeze準拠）。

```
┌─────────────────────────────┐
│ ① 今週のハイライト（1件・大）    │  自動検出された最重要パターンを
│    文章＋簡易ビジュアル          │  1つだけ大きく見せる
├─────────────────────────────┤
│ ② パターンカレンダー            │  体調×行動の重なりをヒートマップ的に
│    （月表示・色の濃淡）          │  視覚化。周期日も重ねて表示
├─────────────────────────────┤
│ ③ 実験結果サマリー              │  進行中/完了実験の効果比較
│    （Before/After比較）         │  （棒グラフ2本比較程度に単純化）
├─────────────────────────────┤
│ ④ 周期との重なりグラフ           │  生理周期フェーズ×体調スコア
└─────────────────────────────┘
```

設計原則:
- グラフより先に「文章化された気づき」を見せる（2.5節に対応）。数値の一覧化はしない。
- 4要素はすべて縦スクロールの中で完結させ、タブ切り替えやフィルタUIを増やさない（疲れない）。
- Freeミアム制限がある場合は要素を「隠す」のではなく「ぼかして見せて理由を添える」（Premiumで解除、7章参照）。

---

## 7. Experiment Layout

「禁止・我慢」ではなく「試してみる小さな挑戦」の選択画面にする。

```
┌─────────────────────────────┐
│ 進行中の実験（あれば最上部に固定） │
│  🔥 16時間断食  Day 5/14        │
│  プログレスリング＋「今日もOK」   │
├─────────────────────────────┤
│ おすすめの実験（Insights連動）    │  気づきカードと同じ根拠を再掲
│  「肌荒れと乳製品の相関から」     │
│  → [乳製品断ちを試す]           │
├─────────────────────────────┤
│ 実験ライブラリ（カード一覧）      │
│  [16時間断食] [14時間断食]      │
│  [カフェイン断ち] [乳製品断ち]   │
│  [カスタム実験（Pro）]          │
└─────────────────────────────┘
```

設計原則:
- 各カードは「名前・期間・想定される変化」を1行ずつ、絵文字/アイコン付きで軽く見せる。
- 開始操作は1タップ（期間や強度の詳細設定は開始後の確認モーダルに逃がす）。
- 進行中の実験は常に1件のみを主役として見せる（同時に何個も並走させて疲れさせない。複数実験の同時進行はPro機能として8章で扱う）。

## 8. Premium / Pro Layout

Premium = **理解を深める**、Pro = **改善実験を進める**、という役割分担を画面上の言葉で明確に伝える。

```
┌─────────────────────────────┐
│  Premium                      │
│  「自分の体をもっと深く理解する」  │
│  ・Insights全履歴の閲覧          │
│  ・周期×体調の長期トレンド        │
│  ・パターンカレンダー全期間表示    │
├─────────────────────────────┤
│  Pro                          │
│  「改善実験をもっと進める」        │
│  ・カスタム実験の作成             │
│  ・複数実験の同時進行             │
│  ・AIによる次の実験提案            │
│  ・Research Contribution Badge  │
└─────────────────────────────┘
```

設計原則:
- 比較表形式にはしない（最大6項目・既存Freeze継承はするが、機能列挙ではなく「できるようになること」を主語にした文章で見せる）。
- Free→Premiumの壁は「ぼかし＋一言の理由」で見せ、Premium→Proの壁は「次の挑戦への招待」トーンで見せる（課金訴求のトーンを段階で変える）。
- 課金導線はInsights/Experiment内の制限箇所からモーダルで直接開けるようにし、「Me」タブ内にも常設ページとして存在させる（3章のNavigation設計と整合）。

---

## 9. Navigation

タブは5つに固定。増やさない・迷わせない・毎日使える構成にする。

```
┌──────┬──────┬───────┬────────┬──────┐
│ Home │Record│Insight│Experiment│  Me  │
│  🏠  │  ✏️  │  📊   │   🔥    │  👤  │
└──────┴──────┴───────┴────────┴──────┘
```

設計原則:
- Recordのタブアイコンは他の4つよりわずかに強調する（中央寄りの視認性の高い位置＋アクセントカラー）。ただしFABのような独立浮遊ボタンにはしない（タブ内に統一し迷いを減らす）。
- 現在地は色（`--plum`）のみで示し、形状変化は付けない（既存 `.nav-item.active` の実装方針を踏襲）。
- タブの追加は将来的にも既存5タブへの機能統合を優先し、新設はFounder承認必須とする。

## 10. Design System

`src/styles/app.css` の実測値を根拠として固定する。架空の数値は使わない。

### Color
| 用途 | 変数 | 値 |
|---|---|---|
| Primary（アクション・強調） | `--rose` | `#c8747b` |
| Primary Light（背景・チップ） | `--rose-light` | `#ecd0d2` |
| Primary Pale（面の背景） | `--rose-pale` | `#f7f2f2` |
| ヘッダー・現在地・締まった色 | `--plum` | `#b14e56` |
| Premium/価値の強調 | `--gold` | `#e8b870` |
| ポジティブ・達成 | `--sage` | `#8abf9a` |
| 背景（全体） | `--cream` | `#F8F3EF` |
| 本文テキスト | `--ink` | `#2d1f1a` |
| 準本文テキスト | `--ink-mid` | `#4a3830` |
| 補助テキスト | `--ink-light` | `#8a7a70` |

### Spacing / Radius
- ベース単位: 8px刻み（16px/20px/24pxをカード内パディングの基準にする）
- Border-radius: 標準カード 14px/12px/16px/10px、大型カード 18px/24px、ピル型（チップ・ボタン） 50px/999px
- タップ領域: 最小 44px（`.nav-item` 実測値準拠）

### Typography
- 本文: `--font-body` = 'Noto Sans JP'
- 見出し・感情的強調（気づきカードの引用文など）: `--font-serif` = 'Shippori Mincho'

### Component Tone
- ボタン: `.btn-primary` 相当（padding 16px、rose背景、白文字）を主要CTAに統一使用
- カード: 白背景＋`--shadow-card`（`0 2px 12px rgba(200,120,140,0.10)`）で统一。強調カードのみグラデーション背景を許可（`--cta-default` 等の既存トークンを継続使用）
- アイコン: ラインスタイル・角丸・絵文字は補助的に使用可（Experiment/Recordのタグ表現など）
- トーン: 温かみ・柔らかさ・上品さ。臨床的・無機質な表現、ゲーミフィケーション的な子供っぽい表現の両方を避ける

## Verdict

# CONDITIONAL GO

理由:
- Product Concept・UX Philosophy・各画面設計は、既存の実測Design System（`src/styles/app.css`）およびPhase2 Governanceで確定済みのInformation Density Freezeと矛盾なく統合できている。
- ただし本設計は文書上の検証に留まり、実際の画面での体感（情報量が本当に疲れないか、気づきカードの文章が実際に響くか、Experiment導線が自然に感じるか）はFounderによる実機確認なしに判定できない。

条件:
1. 本設計を根拠にダミーデータのみのPrototype（`prototype/`）を作成し、Founderが実機で確認する。
2. Founderの実機確認（`docs/rebuild/PROTOTYPE_REVIEW_CHECKLIST.md`）でGOと判定されて初めて、実装Phaseに進む。
3. Prototype確認時に変更が必要な場合は、本文書を更新してから実装に進む（Prototypeが本文書と乖離したまま実装に入らない）。

## ② Founder思想の統合要約

検索の結果、Founder思想は**時期の異なる二つの層**として存在しており、上書きされないまま併存していることが分かった。

### Era 1（2026-04-05〜05-04）: 「kenkou kiroku」ウェルネスブランド期

README.md にのみ明記された思想:

```
核心思想: 「蓄積が意味を持つ体験設計」
　→ 毎日の小さな記録の積み重ねが、ユーザー自身のからだのパターン発見につながる

世界観: 上品・静か・知的・女性的。ブーゲンビリアの気配。
　→ 医療ではなく、寄り添い。

構成要素: チャクラ・食事療法・プチ断食・感情メモの4本柱
カラー: クリームホワイト × ブーゲンビリアピンク（#E63FA8）× ターコイズ（#27B7B3）
フォント: Cormorant Garamond（英語アクセント）× Noto Serif JP（日本語）
```

この時期のUI思想は「ブランドサイト＋日記アプリ」であり、疾患管理・データ資産・課金といった発想は一切登場しない。

### Era 2（2026-05-05〜現在）: 「IPPO」女性疾患管理アプリ期

`d4d8247` のコミットでFounder自身が意図的に方向転換した。この転換以降、UI/UX哲学は**単独の文書として明文化されないまま**、事業戦略文書の中に断片的に埋め込まれている。

```
事業哲学の優先順位（BUSINESS_STRATEGY.md 2-A）:
  1. ユーザー価値（女性が自分の疾患を理解し、主体的に医療と向き合える）
  2. Founderの自由（燃え尽きない持続可能性）
  3. 長期継続性（データの清潔さ）
  4. 売上
  5. 急成長

体験設計原則（BUSINESS_STRATEGY.md 5-A）:
  「記録の障壁ゼロ」「理解の価値最大化」

通知・継続のトーン（GROWTH_STRATEGY.md 6-C/6-D）:
  「督促」ではなく「気づかせる」
  「解約を難しくする」のではなく「したくなくなる」設計
```

これらは実質的にUXへの示唆を含むが、色・フォント・情緒・世界観といった**Era 1が持っていた「見た目・手触り」のレベルの思想は、Era 2では一度も再定義されていない**。2026-07-07付の App Experience Council 群・General Release Experience Council は、いずれも「すでにある実装をどう評価するか」という監査文書であり、「何を美しさ・安心の基準とするか」という原点の再定義ではない。

## ③ 現在との比較

対象: `GENERAL_RELEASE_IMPLEMENTATION_MASTER_PLAN.md` / `GENERAL_RELEASE_EXPERIENCE_COUNCIL.md` / `PHASE2_ARCHITECTURE_FREEZE.md`

### 一致している点

- **「記録の障壁ゼロ」との整合**: README Era1の核心思想「蓄積が意味を持つ体験設計」は、現行の Record 3-card フロー・Draft保護設計（`USER_JOURNEY.md` 第3章）に直接引き継がれている。「毎日小さく記録を積み重ねる」という発想は、疾患管理へ再ポジションされた後も一貫して生きている。
- **「静か」というトーンの部分的継承**: GENERAL_RELEASE_EXPERIENCE_COUNCIL.md の評価観点「疲れないか」「情報量は適切か（Home最大6要素・Insights同時表示4要素以下）」「画面を見ただけで安心するか」は、README の「上品・静か・知的」という世界観と方向性としては矛盾しない。ただしこれは Era1 の言葉を参照して作られたものではなく、独立に導出された基準である。
- **「寄り添い」の残響**: BUSINESS_STRATEGY.md 優先順位1「主体的に医療と向き合えるようにする」という表現は、README の「医療ではなく、寄り添い」というスタンスの遠い延長として解釈できなくはない。ただし現行はAI Signal Insight・診察レポート生成など臨床寄りの機能を明確に志向しており、"医療ではない"という当初の一線は実質的に後退している（この点はBD-031等の免責文言義務化で法的にのみ担保されている）。

### ズレている点

- **世界観そのものの非連続性**: チャクラ・食事療法・断食・感情という「スピリチュアル・ウェルネス」の世界観から、「疾患管理・Research Dataset・k-anonymity」という「臨床・データビジネス」の世界観への転換は、UI/UXの手触り（色・フォント・情緒）のレベルでは一度も言語化・再設計されていない。`PHASE2_ARCHITECTURE_FREEZE.md` の Design System Freeze は実測CSS値（既存実装からの逆算）を根拠にしており、「そもそも何を美しさの基準とするか」という原点には触れていない。
- **manifest.jsonの実装との矛盾**: PWAとしてユーザーに見える公式説明文が今も「チャクラ・食事・断食・感情・基礎体温」のままであり、`GENERAL_RELEASE_SCREEN_MAP.md` 等が描く実装（FREE/Premium/Pro tier・疾患記録・Signal Insight）と完全に乖離している。これは実装忘れであり、General Release前に確認が必要な事実として記録する。
- **実装先行の構造的欠陥との関係**: GENERAL_RELEASE_EXPERIENCE_COUNCIL.md が指摘する3件の重大乖離（ナビアイコン欠落・Insightsレイアウト崩れ・Premium購入導線ゼロ）は、Era2移行後に「見た目・体験の基準」を定めた文書が一度も存在しないまま実装が先行し続けた結果とも解釈できる。App Experience Council群（2026-07-07）は事後的な言語化であり、事前の設計原則ではない。
- **GENERAL_RELEASE_IMPLEMENTATION_MASTER_PLAN.md との関係**: 同文書はPR実行順序・Readinessスコアを扱う実装管理文書であり、UI/UX哲学そのものへの言及はない（体験の善し悪しはApp Experience Council / General Release Experience Councilに委譲する構造になっている）。この構造自体が、「哲学不在のまま実装管理だけが進む」というリスクを裏付けている。

## ④ 最重要文書（Canonical Source）の指定

**今後 General Release / Phase2 / Phase3 すべてのUX設計のCanonical Sourceにすべき単一の既存文書は存在しない。**

理由:

1. **README.md（Era1）** は最も明確な「世界観・情緒」の定義を持つが、Founder自身が `d4d8247` で意図的に上書き（再ポジション）した思想であり、現行のドメイン（女性疾患管理・データ資産・Research Platform）とは前提が異なる。そのまま採用すると「チャクラ・断食」の世界観に逆戻りする矛盾を生む。
2. **docs/BUSINESS_STRATEGY.md 第2章 / docs/GROWTH_STRATEGY.md 6-C・6-D** は現行体制でFounder承認済み・現在も有効な唯一の思想的記述だが、これは事業哲学であり、UI/UXの手触り（色・情報密度・トーン）を直接規定するものではない。
3. **App Experience Council群・General Release Experience Council（2026-07-07）** は最新かつ最も詳細だが、「既存実装の評価・監査」であって「原点の思想定義」ではない。各文書が自ら「新規要素の追加は提案しない」と明記している通り、これらを起点に据えると「今ある実装を追認するだけ」の設計になり、本来あるべき"あるべき姿からの逆算"にならない。

暫定的に最も参照価値が高いのは **docs/BUSINESS_STRATEGY.md 第2章「Business Philosophy」（2-A 事業哲学の優先順位、5-A 記録の障壁ゼロ／理解の価値最大化）** である。Founder承認済み・LEVEL-1 STRATEGIC DOCUMENTという権威づけがあり、現行ドメインとも矛盾しない数少ない文書のためである。ただしこれは**UI/UX専用の哲学文書ではない**ため、恒久的なCanonical Sourceとしては不十分であり、別途「Era2（疾患管理・データ資産）の世界観・情緒・視覚言語を定義する新規文書」をFounderが正式に作成することが望ましい、という事実のみをここに記録する（本監査の性質上、その新規文書の設計・提案は行わない）。

## 最終判定

```
D. 複数存在し統一が必要
```

根拠:
- Era1（README.mdのkenkou kiroku世界観）とEra2（BUSINESS_STRATEGY.md以降の疾患管理・データ資産哲学）が、明示的な廃止・引き継ぎ手続きなく併存している。
- Era1の思想は manifest.json という実装物にそのまま残存し、Era2の実装（画面構成・機能）と矛盾している。
- Era2にはUI/UXの手触りを定義する専用文書が一度も作られておらず、事業哲学（BUSINESS_STRATEGY / GROWTH_STRATEGY）と実装後監査（App Experience Council群）の間に「原点の思想」が空白のまま存在する。
- この状態でPhase2/Phase3のUX設計を進めると、「どの世界観を正とするか」の判断が都度アドホックになるリスクがある。統一（少なくとも「Era1は正式に廃止する」「Era2の世界観を新規に明文化する」のいずれかのFounder Decision）が必要。

## 1. Executive Summary

### Council の総意

IPPO は「最速でユーザーを増やすこと」を目指さない。
目指すのは

> **「記録を続けるユーザーが、自然に増え続ける仕組みを作ること」**

である。

この違いは重要だ。ダウンロード数は「始まり」に過ぎない。
IPPOのネットワーク価値は「記録の長さ × 疾患の深さ」で生まれる。
1,000人が1日だけ記録したデータより、100人が3年間記録したデータの方が価値が高い。

したがって、IPPOの成長戦略の核心は**継続率**にある。

### 設計の核心判断

| 判断 | 内容 |
|---|---|
| 成長の一次指標 | 継続記録率（記録を 90 日以上続けるユーザーの割合）|
| 成長の本質 | 「1 Record = 1 Insight」の即時フィードバック設計 |
| 獲得チャネルの優先順位 | SEO > コミュニティ > SNS > コンテンツ > ASO |
| 広告の位置づけ | 採用しない（BBS-001 / Founder 原則）|
| Founder の発信スタンス | 「アプリ宣伝」ではなく「思想の発信」|
| 海外展開の優先順位 | 台湾 → 韓国 → オーストラリア → EU |

### 最終判定

```
GO

Founder 一人運営で 10 年間継続できる成長戦略が設計できた。
以下の条件のもとで開始する:
  1. コンテンツ発信を今日から始める（Wave2 完了を待たない）
  2. 記録継続率を最重要 KPI として設計に組み込む
  3. 患者コミュニティとの接続を Wave2 Phase B 完了後に開始する
```

## 2. Growth Philosophy

### 2-A. IPPOの成長の本質

```
一般的な SaaS の成長:
  ユーザー数 × ARPU = MRR
  → ユーザー数を増やすことが最優先

IPPOの成長:
  記録を続けるユーザー数 × 記録密度 × 疾患深度 = データ資産価値
  → 「記録が続くこと」が最優先
```

この違いが、すべての成長戦略の判断基準になる。

```
判断基準:
  「この施策は記録継続率を高めるか？」
  → Yes: 採用を検討する
  → No: たとえユーザー数が増えても採用しない

例:
  × バイラルキャンペーン（ダウンロードは増えるが継続しない層が入る）
  ✓ 「30日記録達成」の可視化（記録継続動機の強化）
```

### 2-B. 「プロダクトが成長チャネルである」設計

```
IPPOの理想的な成長は、以下の順序で生まれる:

Step 1: ユーザーが記録し続ける
  → Signal Insight で「自分のパターン」が見えてくる

Step 2: ユーザーが「これは誰かに伝えたい」と感じる
  → 「黄体期に痛みが集中していることが初めてわかった」
  → 「子宮内膜症の症状が可視化されて医師に伝えやすくなった」

Step 3: ユーザーが自発的に紹介する
  → 患者コミュニティ・SNS での口コミ
  → 医師が患者に勧める（Wave3 以降）

Step 4: 新規ユーザーが入る
  → 「同じ疾患を持つ人が使っている」信頼感
  → 既存コミュニティへの参加感

Step 5: Step 1 に戻る

この「1 Record → 1 Insight → 口コミ」ループが
IPPOの永続的な成長エンジンになる。
```

### 2-C. 「10年続く成長」の定義

```
10年続く成長 = 成長速度が「緩やかに加速し続ける」状態

Year 1-2: 種まき期（コンテンツ・コミュニティの基盤を作る）
Year 3-4: 発芽期（口コミが自然に発生し始める）
Year 5-7: 成長期（ネットワーク効果が発動する）
Year 8-10: 安定期（「IPPOを使っていないと疾患管理が不安」という状態）

焦らない。
Year 1-2 に「なぜ伸びないのか」と不安になる必要はない。
重要なのは「記録を続けるユーザーが毎月 10〜20 人増えているか」だけ。
```

## 3. User Acquisition Strategy

### 3-A. チャネル優先順位（全体観）

```
優先度 1: SEO（検索エンジン最適化）
  → 持続的・ランニングコストゼロ・ターゲット精度最高
  → 「子宮内膜症 記録アプリ」「月経痛 管理 アプリ」等の検索意図

優先度 2: 患者コミュニティ
  → 信頼度最高・継続率最高・紹介率最高
  → 子宮内膜症友の会・PCOS コミュニティ等

優先度 3: note / X（SNS）
  → Founder の思想発信 → フォロワー → ユーザー転換
  → Founder が「女性疾患 × データ」の思想リーダーになる

優先度 4: コンテンツ（YouTube / Podcast）
  → 長尺コンテンツで「深く理解した上で使う」ユーザーを獲得
  → 継続率が最も高いチャネル

  → 検索からの自然流入。SEO と並行して実施。

優先度 7: 学会・学術媒体（Wave3 以降）
  → Research Platform 完成後に学会での発表・研究者経由の流入。

採用しないチャネル:
  × 有料広告（Google Ads / SNS 広告）
  × インフルエンサーマーケティング（広告依存 / BBS-001 精神に反する）

## 4. Content Strategy

```
大原則: 「アプリの宣伝」ではなく「Founder の思想の発信」

IPPOの理想的なコンテンツは:
  「女性疾患 × データ × 記録の思想を持つ人が、
   その思想を体現したアプリを作った」

  という文脈で読まれるもの。

NG なコンテンツ:
  × 「IPPOアプリの使い方」（宣伝）
  × 「子宮内膜症の治療法」（医療情報 / YMYL リスク）
  × 「当社のプレスリリース」（機械的）

OK なコンテンツ:
  ✓ 「黄体期に体調が崩れる理由をデータで探った」（体験 × データ）
  ✓ 「3年間の記録でわかった PCOS の季節パターン」（縦断の価値）
  ✓ 「婦人科の診察が変わった話 — データを持って行く前と後」（実用価値）
  ✓ 「なぜ女性疾患のデータは消えてはいけないのか」（哲学）
  ✓ 「Append-Only 設計と縦断データの価値」（技術者向け / 意外な読者層）

## 5. Community Strategy

### 5-A. コミュニティ設計の基本方針

```
IPPOはコミュニティを「作る」のではなく「育てる」。

「作る」（危険）:
  → 管理コスト大・Founder 負荷大・失敗時のリスク大

「育てる」（推奨）:
  → 既存の患者コミュニティ内で IPPO への自然な言及を増やす
  → IPPO のユーザーが自然に繋がる場が生まれるのを待つ
  → Founder はコミュニティを「支援する存在」として外から関わる

10 年後の理想:
  「IPPO のユーザー同士が、IPPO がいなくても繋がっている」状態。
  プラットフォームが消えてもコミュニティが残るほど価値がある。
```

### 5-B. 段階別コミュニティ戦略

#### Wave2 期間（〜2028年）: 外部コミュニティへの参加

```
やること:
  → Founder が X で患者コミュニティのハッシュタグに参加する
    （#子宮内膜症 / #PCOS / #月経困難症 等）
  → 「回答者・共感者」として参加する（宣伝しない）
  → 患者の声から「次に作るべき機能」を学ぶ

やらないこと:
  × Discord / Slack の独自コミュニティの開設（管理コストが大）
  × 患者会への「アプリ宣伝」の売り込み

目標:
  「IPPO を作った人がX にいる」ということを患者コミュニティが知っている状態
```

#### Wave3 期間（2028〜2030年）: ソフトなコミュニティ形成

```
やること:
  → IPPO ユーザー向けのオプトイン型メールニュースレター開始
    （月 1 回 / 「今月のデータで気づいたこと」等）
  → note のメンバーシップで「深い記録実践者」のコミュニティを形成
  → 患者会との MOU 後、研究貢献の結果報告を共有する

形態:
  → クローズドより「緩やかなオープン」
  → Discord は重すぎる。Substack / note が適切。

目標: 月次ニュースレター購読者 1,000〜3,000 人
```

#### Wave4 以降（2030年〜）: Disease Community の形成

```
やること（Similarity UI 公開後 / Phase 4 以降）:
  → 「同疾患グループのユーザーが匿名でつながれる」機能の設計
    （BD-029 Layer B: Phase 4 以降に開放）
  → 「私と同じパターンの人が 12 人いました」の体験が口コミを生む
  → 疾患別の「記録継続グループ」の形成（ゲーミフィケーションではなく共感ベース）

注意:
  × コミュニティをプロダクトの「外側」に作らない
  → コミュニティ体験はプロダクトの「内側」に組み込む（Similarity Match）
  → SNS コミュニティは「外側の補完」として自然に形成されるのを待つ
```

## 6. Retention Strategy

### 6-A. 継続率の定義と目標

```
IPPO における継続率の定義:

  記録継続率（最重要）:
    「過去 30 日以内に最低 1 件の Record を保存したユーザーの割合」
    目標: 60% 以上（月次 WAU / MAU 比）

  Premium 継続率:
    「3ヶ月後も有料サブスクリプションを維持しているユーザーの割合」
    目標: 75% 以上（3ヶ月継続率）

  縦断継続率（最高価値）:
    「1年後も記録を続けているユーザーの割合」
    目標: 40% 以上（12ヶ月継続率）

なぜ記録継続率が最重要か:
  → 記録が続く = データが蓄積される = ネットワーク価値が増す
  → 記録が続く = Signal Insight の精度が上がる = ユーザー価値が増す
  → これは「継続の自己強化ループ」である
```

### 6-B. 「1 Record = 1 Insight」の設計原則

```
BD-029（NETWORK_EVOLUTION_COUNCIL）が定義した
「Participation Loop Layer A（個人価値ループ）」を実装する。

設計原則:
  「記録したら、何か気づきが返ってくる」を保証する。
  気づきは小さくていい。「今日の痛みスコアは先週より 0.2 高い」でも価値がある。

段階別 Insight フィードバック:

  Day 1〜7（Free / 無記録期間）:
    「最初の記録を保存しました。7日間記録すると最初のパターンが見えてきます」
    → 次のマイルストーンを明示する

  Day 8〜30（記録蓄積期）:
    「今週の痛みスコアの平均は 4.2 でした」（基本統計）
    「月経周期 28 日目が近づいています」（次の記録促進）
    → 「あなたの記録が育っている」感覚を持たせる

  Day 31〜90（Longitudinal 体験期 / Premium の価値が出始める）:
    「先月と比較すると、黄体期の痛みスコアが 0.5 増加しています」（Longitudinal）
    「あなたは子宮内膜症グループの中で記録密度上位 20% です」（Cluster 比較）
    →「他の人より深く理解できている」感覚

  Day 91〜365（Signal Insight 体験期 / Phase D 完了後）:
    「あなたの症状は黄体期（Day 17〜28）に 73% 集中するパターンがあります」（AI Insight）
    「睡眠スコアが 7 以下の翌日は痛みスコアが平均 1.1 高い傾向があります」（Pattern Discovery）
    → 「IPPO がなければわからなかった」感覚

  Day 365 以降（縦断の価値体験期）:
    「1年間の記録が完了しました。あなたの縦断データが研究に貢献しています」
    → 「自分の記録が社会に繋がっている」感覚（Participation Loop Layer C）
```

### 6-C. 記録継続を支援する通知設計

```
通知の設計原則:
  「督促」ではなく「気づかせる」通知

NG な通知:
  × 「今日の記録をしていません！」（プレッシャー）
  × 「記録を続けないとデータが台無しです」（脅し）
  × 毎日の Push 通知（うるさい / OFF にされる）

  ✓ 「今週のパターンが見えてきました。確認しますか？」（好奇心）
  ✓ 「月経周期のタイミングが近づいています」（タイミングの提示）

  → 押しつけず、ユーザーが自分に合った頻度を選ぶ
```

### 6-D. 解約防止の設計方針

```

     定義: Record を持つユーザーのうち Disease Entity を登録しているユーザーの割合
     目標値: 70% 以上

```
四半期 KPI セット（半日で確認可能）:

  11. オーガニック流入率
      定義: 広告 / 有料施策によらないインストールの割合
      目標値: 80% 以上
      なぜ重要: Founder 原則「広告依存しない」の遵守確認

  12. コンテンツ流入率
      定義: note / X / SEO からのインストールの割合
      目標値: 40% 以上（オーガニックの過半数）
      なぜ重要: コンテンツ戦略の効果測定

  13. 12ヶ月継続率（縦断継続率）
      定義: 登録 12ヶ月後も記録を続けているユーザーの割合
      目標値: 40% 以上
      なぜ重要: データ資産の長期価値の指標

  14. LTV（ライフタイムバリュー）
      定義: 1ユーザーあたりの期待累計収益
      計算: ARPU / 月次解約率
      目標値: 20,000 円以上（ARPU 1,000円 / 月次解約率 5% = 20,000円）

      定義: 「IPPO を友人や知人に勧めるか」（0〜10 点）

### 10-E. 採用しない KPI

```
Founder 一人運営で意味がない / 混乱を招く KPI:

  × DAU（日次アクティブユーザー）
    理由: IPPOは毎日使うアプリではない（症状がある時に記録する）
          DAU を最大化しようとすると「無意味な通知」につながる

  × ページビュー / セッション数
    理由: 「見るだけ」は IPPO では価値がない。「記録する」が価値。

  × ダウンロード数
    理由: インストールして記録しないユーザーは IPPO の価値を生まない

  × CAC（顧客獲得コスト）
    理由: 有料広告を使わないため CAC の最適化は不要

  × K-factor（バイラル係数）
    理由: バイラル施策を実施しないため測定不要

  × 広告クリック率（CTR）
    理由: 広告を使わない
```

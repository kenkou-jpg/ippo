## 現状評価

現在のippoは、疾患データの**記録基盤は堅牢**だが、**分析エンジンの設計が3年後の拡張に耐えられない状態**にある。

最大の問題は `app-legacy.js`（11,486行）に分析・UI・保存が混在するGod Object構造だ。特に、体温分析・フレア検出・因子相関の5関数が `window.*` 経由でのみアクセス可能という設計は、テスト不能・バグ混入リスク・将来拡張の障壁になっている。

一方で、**保存処理とSupabase連携は安定しており、データ消失リスクは低い。** 既存の `insight-engine.js` は設計が清潔で、拡張の土台として使える。Claudeへの接続も稼働中だが、「生データをそのまま渡す」現状では推論の深さが制限されている。

## 推奨アーキテクチャ

**Option B — モジュール分離（Strangler Pattern）**

一括リライトは稼働中アプリへのリスクが過大。新機能は全て新規ファイルとして追加し、`app-legacy.js` の分析関数を段階的に置き換える。**保存処理・認証・同期には一切手を加えない。**

```
新機能の追加ルール:
  app-legacy.js への追記 → 禁止
  新規ファイルとして追加 → 必須
  window.* への追加 → 禁止
  既存window.*の段階置換 → OK（Strangler Pattern）
```

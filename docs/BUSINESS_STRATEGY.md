## 1. Executive Summary

### Council の総意

IPPO は「女性疾患の縦断データ資産を構築するプラットフォーム」である。
Wave1 の完了により、世界最高水準のデータ設計基盤（Layer 0〜8）が完成した。
しかし FOUNDER_STRATEGIC_REVIEW（IPPO-STRATEGIC-REVIEW-001）が指摘した通り、

**「ビジネスモデル明確性: 42/100 / 市場戦略: 35/100」**

という事業設計の空白が存在する。本 Council はこの空白を埋める。

### 設計の核心判断

| 判断 | 内容 |
|---|---|
| 事業の本質 | 「B2C 収益で成長し、Research 収益で爆発する」二段ロケット |
| 価格設計原則 | 安すぎず高すぎず。継続できる価格が最善 |
| 最大の資産 | データそのもの（時間だけが作れる資産）|
| Founder の守るべきもの | 一人運営・データの清潔さ・時間の自由 |
| やらないこと | 営業組織・VC 依存・急成長・ユニコーン |

### 最終判定

```
GO — 条件付き推奨戦略

事業として成立する。ただし以下が前提:
  1. ユーザー価値の短期化（Wave2 中間価値の設計）
  2. 規制対応の法的整理（AI / Research Platform）
  3. 医師アドバイザーの招聘（Wave2 Phase D 前）
```

## 2. Business Philosophy

### 2-A. 事業哲学の定義

IPPO の事業哲学は以下の優先順位で成立する:

```
優先順位 1: ユーザー価値
  「女性が自分の疾患を理解し、主体的に医療と向き合えるようにする」
  これが崩れると、データの価値も崩れる。

優先順位 2: Founder の自由
  「10年後も Founder が喜んでこの事業をやっている」状態を維持する。
  燃え尽きる成長は持続可能な成長ではない。

優先順位 3: 長期継続性
  「10年後のデータ価値」が「今日の売上」より重要な局面がある。
  短期利益のためにデータの清潔さを犠牲にしない。

優先順位 4: 売上
  年収 1 億円で十分。それ以上を無理に追わない。

優先順位 5: 急成長
  ネットワーク効果が自然に発生するまで、無理な拡大をしない。
```

### 2-B. 「データ資産を育てる会社」の意味

IPPO のデータ資産は「記録の長さ × 疾患の深さ × Consent の清潔さ」の三乗で価値が増す。
この複利構造を理解することが、すべての事業判断の基盤になる。

```
今日の 100 件の Record は、10年後に「10年分の縦断データ」として
競合が追いつけない資産になる。

今日の 1 件の Consent が不完全であれば、
10年後の Research Dataset の信頼性が 1% 毀損される。

このため:
  「ユーザーを急増させること」よりも
  「ユーザーが記録を続けること」を優先する。
```

### 2-C. 競合との差別化（事業視点）

| 競合 | 強み | IPPO との差別化 |
|---|---|---|
| Flo（7,000万 MAU）| 圧倒的ユーザー数 | Consent 設計・Append-Only・Research 品質で差別化 |
| Clue（1,200万 MAU）| 研究連携実績 | 縦断データの決定論的再構築・k-anonymity 埋め込みで差別化 |
| ルナルナ（650万 MAU）| 日本市場シェア | 疾患特化・Similarity Network・Research Platform で差別化 |
| Natural Cycles | FDA 認定 | 疾患横断・縦断深度・AI 基盤で差別化 |

**IPPOの不模倣資産:**
- Layer 0〜12 の決定論的再構築チェーン（技術不模倣）
- 「症例（Case）」をネットワークノードにした設計（設計不模倣）
- 最初から k-anonymity を埋め込んだ Consent 設計（歴史不模倣）

## 3. Business Model

### 3-A. 顧客定義

IPPO の顧客は 3 層に分かれる:

```
顧客層 1: B2C（患者・ユーザー）
  誰: 女性疾患（子宮内膜症・PCOS・月経困難症等）を持つ女性
  なぜ払うか: 自分の症状パターンを理解し、医師との会話を改善する
  課金タイミング: 月次サブスクリプション
  価格帯: 月 500〜2,000 円

顧客層 2: Research（研究機関）
  誰: 大学医学部・女性疾患研究者・製薬企業 R&D 部門
  なぜ払うか: 倫理的に完璧な縦断 Research Dataset を入手する
  課金タイミング: Dataset ライセンス（年次 or 一括）
  価格帯: 年 100〜1,000 万円（スコープによる）

顧客層 3: B2B（医療機関）
  誰: 婦人科クリニック・産婦人科病院
  なぜ払うか: 患者の自宅記録データを診察に活用する
  課金タイミング: SaaS 月次課金
  価格帯: 月 3〜10 万円/院
```

### 3-B. 収益の柱（永続事業設計）

```
柱 1: B2C Premium Subscription（主力 / Wave2 から）
  特性: 予測可能な毎月の収益
  Founder 負荷: 低（一度作れば自動課金）
  スケール方法: SEO・SNS・コミュニティ・口コミ

柱 2: Research Dataset License（爆発力 / Wave3 から）
  特性: 件数は少ないが単価が高い
  Founder 負荷: 中（IRB 対応・契約交渉は 1 回きり）
  スケール方法: 学術論文引用 → 権威ループ

柱 3: B2B Clinic API（安定収益 / Wave4 から）
  特性: チャーンが少ない（医療機関は乗り換えコストが高い）
  Founder 負荷: 低〜中（セットアップ後は自動運用）
  スケール方法: 医師アドバイザー経由の紹介

柱 4: Disease Intelligence API（将来 / Wave5〜）
  特性: 製薬・医療機器企業向け高単価 API
  Founder 負荷: 低（API 提供のみ）
  スケール方法: Research 実績 → API 需要
```

### 3-C. 「やらないビジネスモデル」

IPPO が明示的に採用しない収益モデル:

```
× 広告収益: ユーザーの健康データを広告に使うことは信頼を毀損する
× データブローカー: BD-030（ZERO TOLERANCE）に抵触する
× 製薬会社への個人データ販売: BD-030 絶対禁止
× フリーミアム乱用: 無料ユーザーが多すぎると Research Dataset の密度が下がる
× VC 依存の急成長: Founder の自由を失う
```

## 4. Pricing Strategy

### 4-A. 価格設計の哲学

```
「高すぎると継続されない。安すぎるとデータ密度が下がる」

女性疾患患者の月額支出感度:
  自己負担医療費: 月 5,000〜30,000 円（婦人科通院 + 薬）
  美容・健康サプリ: 月 3,000〜10,000 円
  → IPPO の月額 1,000 円は「医療費の 1/10」であり許容範囲内

価格設定原則:
  1. 「月 1,000 円以下」に見せる（心理的障壁を下げる）
  2. 「年払いで 20% 割引」（LTV 向上・解約率低下）
  3. 「学生・低所得者向け割引」は将来検討（データ密度向上）
```

### 4-B. B2C 価格体系

#### Free Plan（無料）

```
目的: ユーザー獲得・データ密度基盤の確保

機能:
  ✓ Record 記録（無制限）
  ✓ 基本 Signal 可視化（30日分）
  ✓ 月経周期トラッキング
  ✓ 基本 Disease 登録

制限:
  × Longitudinal Analysis（90日以上）
  × Disease Signal 比較
  × Signal Insight（AI）
  × Similarity Match（Phase 4 以降）
  × Data Export

価格: 無料
```

**Council 判断の根拠:**
無料プランを設けることでユーザーが「まず使う」ハードルが下がる。
無料ユーザーの Record も（Consent あれば）Research Dataset に貢献する。
無料ユーザーを「データ貢献者」として位置づける。

```
目的: 個人ユーザーの継続的価値提供

機能:
  ✓ Free Plan のすべて

なぜ 980 円か:

## 5. Subscription Design

### 5-A. 無料 vs 有料の境界設計原則

```
無料にするもの（「記録する」行動そのもの）:
  → Record を無料にすることがデータ資産の源泉
  → ユーザーが記録し続ける限り、データは増える

有料にするもの（「理解する」体験）:
  → 記録したデータから「意味」を取り出す体験
  → Longitudinal Analysis / Signal Insight / Similarity Match

境界設計の哲学:
  「記録の障壁ゼロ」「理解の価値最大化」
```

### 5-B. ユーザーフロー設計（継続率最大化）

```
Day 0〜7（無料体験）:
  → 基本記録を体験する
  → 「7日続いた」フィードバック
  → 「30日分のデータが揃うとパターンが見え始める」メッセージ

Day 30（最初の Premium 提案）:
  → 「あなたの 30 日のパターンを分析しました」
  → Longitudinal Analysis の Preview（有料ロック）
  → Premium への転換提案

月 3 以降（継続動機の維持）:
  → 「あなたの記録は同疾患グループの上位 X% の密度です」
  → 「あなたのデータが将来の研究に貢献しています」（Research Contribution）
  → 季節・フェーズ変化の Insight 通知

年払い転換（月 6〜12）:
  → 「1年分のデータで見えてくること」の予告
  → 年払い割引の提案（12ヶ月継続ユーザーに）
```

### 5-C. LTV 最大化ではなく「継続価値最大化」

```
Council の重要な判断:

  LTV 最大化（解約させない施策）は追わない。
  → 「解約できない仕組み」は信頼を毀損する

  継続価値最大化（継続したくなる施策）を追う。
  → 「記録を続けると、自分の理解が深まる」体験の設計

  具体的禁止事項:
    × 解約困難な UI 設計（ダークパターン）
    × 値下げを交渉させる解約フロー
    × データ削除の脅しによる継続誘導

  具体的推奨事項:
    ✓ 継続記録への「成長フィードバック」
    ✓ Research Contribution の可視化（「あなたのデータが使われた」）
    ✓ 年払い転換インセンティブ（価値訴求型）
```

## 6. Research Business Strategy

### 6-A. Research Business の本質

```
Research Business の本質は「時間が作るモート」である。

今日の Research Dataset（Wave2）:
  - Case 数: 数百〜数千
  - 縦断期間: 最長 2〜3 年
  - 価値: 「参考になる」レベル

2030年の Research Dataset（Wave3〜4）:
  - Case 数: 数万
  - 縦断期間: 最長 5〜8 年
  - 価値: 「これなしに論文が書けない」レベル

この差は時間でしか作れない。
製薬会社も大学も、この差を買う。
```

### 6-C. ライセンス設計

```
Research License の種類:

  L1: Academic License（大学・非営利）
    用途: 学術論文・学位論文
    条件: IRB 承認 + Founder 承認 + 引用義務
    制限: 商用利用禁止 / 再配布禁止
    価格: Standard の 30% 割引

  L2: Commercial Research License（製薬・医療機器）
    用途: 新薬・診断ツール開発
    条件: IRB 承認 + Founder 承認 + 利用用途明示 + 守秘義務
    制限: 第三者提供禁止 / IPPO への研究成果フィードバック義務
    価格: Standard 価格

  L3: Government License（政府・公的機関）
    用途: 政策立案・実態調査
    条件: Founder 承認 + 利用目的明示 + 公開前審査
    価格: Case ごと
    特記: 調査結果の社会的発信により IPPO のブランド価値が向上

  禁止ライセンス:
    × データブローカーへの再販
    × 個人特定を目的とした利用
    × AI 学習データとしての第三者への転売
```

  負荷: 低

Wave3 期間（2028〜2030）:

## 7. B2B Strategy

### 7-A. B2B の基本方針

```
Founder 一人運営を維持するため、B2B は「少数高単価」に限定する。

B2B に手を出さない状況:
  × 10クリニックへの同時営業
  × カスタマイズ開発を伴う B2B 案件
  × SLA（99.9% 保証）を求める大企業案件
  × 導入コンサルティングが必要な案件

B2B に手を出す状況:
  ✓ 月 5 万円以上 × 自動化できる × 3 クリニック以内
  ✓ API 提供のみで完結する案件
  ✓ 医師アドバイザー経由の紹介案件
```

### 7-B. 段階別 B2B 展開

#### Phase 1: B2B は始めない（〜Wave2 完了 / 2028年）

```
理由:
  B2B 展開は「病院・クリニックが IPPO を信頼する」ことが前提。
  信頼は「研究実績 × ユーザー数 × 医師アドバイザー」で形成される。
  Wave2 完了前に B2B を始めても信頼基盤がない。

この期間にやること:
  → 婦人科医アドバイザー 1〜2 名の招聘
  → 医師向けの IPPO 紹介資料（1 枚）の準備
  → 「クリニック向けダッシュボード」の設計（実装はまだしない）
```

#### Phase 2: パイロット（Wave3 / 2028〜2030年）

```
対象: 医師アドバイザーの所属クリニック or 紹介クリニック 3 院
条件:
  → 患者が IPPO を使っていること（患者側の Record が前提）
  → 医師がダッシュボードを試用したいと自発的に申し出ること
  → Founder が対応できる範囲（月 2 時間以内）

価格: パイロット期間（6ヶ月）は無償 → Standard 価格へ移行

目標:
  → 医師の「使い続けたい」という声の収集
  → クリニック導入のユースケースの文書化
  → 「医師が IPPO を患者に勧める」エコシステムの実証
```

#### Phase 3: B2B スケール（Wave4〜 / 2030年〜）

```
対象: 婦人科クリニック（全国 / セルフサービス導入）
方法:
  → API + ドキュメントのセルフ導入（営業なし）
  → 既存 EMR ベンダー（メドレー等）との API 連携
  → 医師コミュニティ（日本産科婦人科学会等）での口コミ

目標 Case 数:
  2030年: 10 院
  2032年: 30 院
  2035年: 100 院（この規模で年収 1 億円は十分）

Founder 負荷（2030年以降）:
  → API 維持・月次ログ確認: 月 5〜10 時間
  → 新規導入サポート（セルフ導入ドキュメント整備）: 月 2〜5 時間
```

### 7-C. 病院・大学病院との関係

```
大病院・大学病院との関係は「B2B 契約」ではなく
「Research 提携」として位置づける。

理由:
  大病院との B2B 契約は:
    - 意思決定に 1〜2 年かかる
    - カスタマイズ要求が多い
    - セキュリティ審査が厳しい
    - Founder 一人では対応不可

  代わりに:
    - Research Dataset License で資金提供を受ける
    - 医師が個人の立場でアドバイザーになる
    - 共同研究という形で関係を深める

  この方が:
    - Founder 負荷が低い
    - 権威性が高い（「○○大学との共同研究」）
    - 長期関係になる
```

## 11. Risk Assessment

### 11-A. 収益リスク

```

  深刻度: HIGH
  原因: SEO・ASO・SNS のリード獲得に時間がかかる

  最悪ケース: MAU が 500 未満で停滞 → Wave3 スコープを縮小して継続

リスク R-B02: Premium 転換率が低い（5% 以下）
  深刻度: MEDIUM
  原因: 無料プランで十分と感じるユーザーが多い
  軽減:
    → Signal Insight をより早期に（Wave2 Phase D 完了時）提供

リスク R-B03: Research Dataset の顧客が見つからない
  深刻度: MEDIUM
  原因: 研究機関との接触チャネルがない
  軽減:

    → 初回は低価格（or 無償）で実績を作る

  深刻度: MEDIUM

  軽減:
    → 患者疾患コミュニティへの深い関与で「代替不可」ポジションを確立
    → Research Dataset の学術実績で差別化

## 12. Founder Recommendations

### FR-B01（最優先）: 現在の事業数値を把握・宣言する

```
IPPO-STRATEGIC-REVIEW-001（CR-01）が既に指摘した通り、
「現在のユーザー数・収益・継続率」が不明なままでは
Wave2 の意義を正当化できない。

Founder は以下を確認し、自分自身に宣言すること:
  □ 現在の MAU
  □ 有料ユーザー数 / MRR
  □ 最多疾患グループの Case 数
  □ 3ヶ月継続率

判断基準:
  MAU < 100: ユーザー獲得を Wave2 と同等優先度で実施
  MAU 100〜500: Wave2 進行 + 中間価値の早期公開
  MAU 500+: Wave2 フル進行
```

### FR-B02: 医師アドバイザーを Wave2 Phase D 前に招聘する

```
必要な理由:
  1. AI Signal Insight の医学的正確性担保
  2. 規制リスク（SaMD 該当判断）のアドバイス
  3. Research Dataset の学術的信頼性向上
  4. クリニック B2B への最初の入口

採用方法:
  → 婦人科専門医（子宮内膜症 / PCOS 専門）
  → ストックオプション or アドバイザー報酬（月 10〜20 万円相当）
  → 月 2〜4 時間の関与で十分

これは Wave2 の「最も安価で最も価値が高い投資」である。
```

### FR-B03: コンテンツを今すぐ始める

```
SEO・SNS・YouTube・note は「今日種を蒔いて 6〜12 ヶ月後に実る」。
Wave2 完了を待ってからコンテンツを始めても遅すぎる。

推奨コンテンツ:
  note:
    「子宮内膜症と向き合う記録のすすめ」
    「自分の症状パターンを発見した話」
    「データで疾患を理解するとはどういうことか」

  X（Twitter）:
    Founder が自身の疾患データ管理の経験を発信
    医療 × テクノロジーの視点での発信

  YouTube（将来）:
    「IPPO の使い方」より「女性疾患とデータの話」

コンテンツの姿勢:
  「アプリの宣伝」ではなく「Founder の思想の発信」
  製品がコンテンツについてくる設計
```

### FR-B04: 規制リスクの法的整理（Phase D 前必須）

```
AI Platform（Signal Insight）着手前に:
  □ 弁護士 or 薬事コンサルへのワンショット相談（10〜30 万円）
  □ 「医療機器プログラム（SaMD）への該当可否」の法的見解取得
  □ Research Dataset の「匿名加工情報」要件の確認
  □ プライバシーポリシーの要配慮個人情報対応

これは「保険」ではなく「必須確認」である。
実装後に「SaMD 該当」と判明したら撤回・改修コストは数倍になる。
```

### FR-B05: Research Business を「将来の収益柱」として今から設計する

```
今すぐやること:
  → Research Dataset の「将来の顧客像」を 3 社書き出す
    （大学名 / 研究テーマ / 担当者候補）
  → 学会（日本産科婦人科学会 / 子宮内膜症学会）の年次大会に
    Wave3 完了後に参加するスケジュールを今から押さえる
  → Research ページ（landing page）を Wave2 Phase F 前に公開する

やらないこと:
  × Wave2 期間中に Research Business の営業活動
  × IRB なしでの Research Dataset 提供
  × 顧客不明のまま Research Platform を実装する
```

### FR-B06: Exit 戦略を今から意識する

```
10年後の Exit オプション（優先順）:

  選択肢 A: 永続運営（推奨）
    → 年収 1〜3 億円の事業を Founder 個人が運営し続ける
    → Disease Ontology が国際的に引用されるようになれば
      「Founder が事業そのもの」になる
    → デメリット: Founder が抜けると事業が止まる

  選択肢 B: スモール M&A（条件次第で推奨）
    → 買い手候補: 製薬企業 / 医療 IT 企業 / 患者向けプラットフォーム
    → 評価額: ARR × 5〜15 倍 + データ資産プレミアム
    → 2031年（標準シナリオ / ARR 1 億円）時点で
      50〜150 億円の評価が可能
    → Founder の意向次第で選択肢として開いておく

  選択肢 C: PE 売却（低推奨）
    → PE は「売上最大化」を求める。Founder 哲学と相容れない。
    → ユーザーデータの商業利用圧力がかかる可能性がある
    → 基本的に選択しない

  選択肢 D: IPO（非推奨）
    → 上場コスト・投資家対応・IR 業務が Founder の自由を奪う
    → Founder 哲学と根本的に相容れない
    → 考慮しない

推奨 Exit 方針:
  「2036年までは永続運営。
   その時点で Founder が 10年後もやりたければ続ける。
   疲れた・やりたいことが変わった・適切な買い手が現れた場合は
   スモール M&A を検討する。
   それまで IPO も PE も考えない。」
```

### Council 最終判定

```
CONDITIONAL GO

IPPOの事業は、以下の条件のもとで、
Founder 一人で 10 年以上持続可能に運営でき、
年収 1 億円を達成し、ユーザーへ最大価値を届けられると判断する。
```

### 推奨戦略

```
■ 絶対にやるべきこと

  1. B2C サブスクリプションを今すぐ価格設定し、課金を開始する
     （Free / Premium 980円 / Pro 1,980円 の 3 層設計）

  2. 医師アドバイザーを Wave2 Phase D 前に 1 名招聘する

  3. AI Signal Insight の規制確認を Phase D 着手前に完了する

  4. コンテンツ（note / X）を今日から始める
     （Wave2 完了を待たない）

  5. Research Dataset の「最初の顧客候補」を 3 社書き出す

  6. 現在の MAU・有料ユーザー数・継続率を把握・宣言する
```

---

### 非推奨戦略

```
■ 絶対に避けること

  1. VC からの資金調達（Founder の自由を失う）

  2. 営業チームの採用（Founder 哲学と相容れない）

  3. Wave2 完了前の B2B Clinic 展開（信頼基盤がまだない）

  4. IPO・PE 売却の検討（10年以内）

  5. Research Dataset の IRB なし / k<5 での提供（BD-030 / ZERO TOLERANCE）

  6. AI Signal Insight で診断・治療・緊急度判定（BD-031 絶対禁止）

  7. 週 60 時間以上の実装（持続可能性の毀損）

  8. 月額 500 円以下の価格設定（データ密度を支えるコストを下回る）
```

### Council 最終所見

```
IPPOには、10年後に「女性疾患の縦断データで世界標準になる」可能性がある。

この可能性は技術設計によってすでに構造的に担保されている。
Layer 0〜12 のデータ設計、Consent Immutability、k-anonymity の埋め込み、
これらは競合が今すぐ模倣を始めても 5〜10 年かかる。

しかし可能性は自動的に現実にならない。

必要なのは:
  「ユーザーが記録を続ける理由」の設計
  「研究者がデータを使いたくなる理由」の設計
  「Founder が 10 年後もこの事業を好きでいる理由」の設計

この 3 つがすべて揃ったとき、
IPPO は「Founder 一人で 10 年持続可能、年収 1 億円超、
世界の女性疾患研究に貢献するプラットフォーム」になる。

Council は全員一致で推奨する:

  「今日から事業として動かせ。
   完璧な設計を待つな。
   ユーザーと一緒に育てろ。
   データは時間が作る。
   時間を無駄にしないことが最大の競争優位だ。」
```
